This browser has no WebHID

navigator.hid is unavailable, so nothing here can reach the keypad. Use Chrome, Edge, Opera or another Chromium browser — Firefox and Safari have not implemented WebHID.

Also note that navigator.hid defaults to self in Permissions Policy, so this page must be the top-level document: it will not work inside a cross-origin iframe.

Layout — 12 keys · 2 knobs

Layers are switched on the keypad itself — the small button on its left edge. The indicator LEDs beside the knobs show which layer is live, and flash once when you press it. The tabs here only choose which layer you are editing.

Ready. Nothing has been sent to the keypad.

Read from keypad uses 0xFA and 0xFB — both confirmed against this hardware. They are reads and change nothing on the device. A binding loaded from the keypad is written back byte for byte unless you edit it, so fields this tool has not fully decoded survive a round trip untouched.

Reset

Empties every binding on layer 1 in this page only. The keypad keeps working exactly as it does now until you write.

Re-declares the keypad as 12 keys, 2 knobs and rewrites the backlight. Use this if only some keys light up or respond — that means the keypad has been told it is a different model. Key bindings are not affected.

Writes an empty binding to every key and knob action on layer 1, so nothing on that layer does anything. Other layers are untouched. If the layer holds macros this erases them from the device — export first.

Before you write

One write, all three layers. Writing sends every binding you have set, layer by layer, then the backlight for each layer. Slots you never touched are left alone.

Bindings are kept in this browser under localStorage, so the page remembers them. That is a convenience, not a backup — use Export for anything you care about.

This page never sends 0xEF, the command that puts the keypad into its bootloader.
